## 1. 重启后什么还在、什么会丢

| 项 | 容器重启后 | 说明 |
|----|------------|------|
| 代码仓库 `/workspace/code/...` | ✅ 一般在 | 持久卷上的 checkout |
| 模型 W8A8 `/workspace/models/DeepSeek-V4-Flash-W8A8` | ✅ 一般在 | 同上 |
| GGUF ` /workspace/models/cache/dsv4_layer{0..42}.gguf` | ✅ 一般在 | 同上 |
| `kt-kernel/python/kt_kernel_ext*.so` | ✅ 一般在 | 已编好的扩展，**不必每次重编** |
| `pip install -e kt-kernel` 注册 | ❌ 会丢 | editable 装在容器内 site-packages |
| 系统包 `libhwloc15` 等 | ❌ 可能丢 | 新容器需重装 |
| CANN / torch_npu | ✅ 一般在 | 镜像内自带；launch 脚本会 `source set_env.sh` |

**典型踩坑**：只加了 `PYTHONPATH=kt-kernel/python`，没有 `import kt_kernel` → 日志出现 `[KT] kt_kernel not available` → MoE 全走 NPU → **NPU OOM**。

## 2. 快速 checklist（推荐顺序）

```bash
export REPO=/workspace/code/ktransformer/ktransformers-AK
export PYBIN=/usr/local/python3.11.14/bin/python3.11
cd "$REPO"
```

### ① 系统依赖（每个新容器一次）

```bash
apt-get update && apt-get install -y libhwloc15
```

- **运行时**只需 `libhwloc15`（加载已有 `.so`）。
- **仅当要重新编译** `kt-kernel` 时才需要：`apt-get install -y libhwloc-dev pkg-config`。

### ② 预检（必须通过）

```bash
bash tools/p27_e2e_preflight.sh
```

期望输出末尾：

```text
[preflight] OK: all 43 GGUF files present ...
[preflight] kt_kernel_ext:
   .../kt-kernel/kt_kernel/kt_kernel_ext.cpython-311-aarch64-linux-gnu.so
[preflight] OK: kt_kernel_ext 在仓库 kt-kernel 包内
[preflight] PASS
```

### ③ 选手写 NPU 卡

```bash
npu-smi info
# 选 HBM 占用低的物理卡，例如 7：
export ASCEND_RT_VISIBLE_DEVICES=7
```

### ④ Graph 模式启动（验证准确性 / 日常推理）

```bash
SGLANG_NPU_PROFILE_ENABLE=0 \
PORT=8001 \
ASCEND_RT_VISIBLE_DEVICES=7 \
./tools/p27_launch_ds4flash_npu_num_expert_0.sh
```

日志中应出现 **`Decode npu graph: True`**，且 **不应** 出现 `[KT] kt_kernel not available`。

### ⑤ F2 冒烟

```bash
PORT=8001 bash tools/p27_curl_f2_prompts.sh
```

判据：无 `! ! !` / `( ) 1) 2) 3)...` 式退化；中英文能续写合理内容（base 模型不考核指令遵循）。详见 Handoff **Z.8**。

## 3. `kt_kernel` 无需 pip 的加载方式

launch / preflight 脚本已内置 `tools/p27_ensure_kt_kernel.sh`：

- 自动创建 `kt-kernel/kt_kernel` → `python` 的 symlink（`setup.py` 里包名 `kt_kernel` 映射到 `python/` 目录）
- 设置 `PYTHONPATH=$REPO/third_party/sglang/python:$REPO/kt-kernel`

**preflight PASS 即可直接 launch，通常不需要 `pip install -e`。**

> **注意**：`PYTHONPATH` 必须是 `$REPO/kt-kernel`（父目录），**不能**只写 `$REPO/kt-kernel/python`。若 launch 脚本被改回旧写法，会出现 **`ImportError: kt_kernel is not installed`**，而 `p27_e2e_preflight.sh` 仍可能 PASS（preflight 已走 `p27_ensure_kt_kernel`）。

手动自检：

```bash
source tools/p27_ensure_kt_kernel.sh
p27_ensure_kt_kernel "$REPO"
export LD_LIBRARY_PATH="/usr/local/kml/lib:${LD_LIBRARY_PATH:-}"

"$PYBIN" -c "
from kt_kernel import kt_kernel_ext, generate_gpu_experts_masks
print('OK', kt_kernel_ext.__file__)
"
```

## 4. 何时才需要 `pip install -e` 或重编 C++

| 场景 | 是否需要 |
|------|----------|
| 容器重启，preflight PASS | **否**，直接 launch |
| `kt_kernel_ext*.so` 文件不存在 | **是**，按 §5 重编 |
| 修改了 `kt-kernel/` 下 C++ 源码 | **是**，重编并 `cp` 到 `kt-kernel/python/` |
| 仅想 pip 注册（可选） | 需先装 **`libhwloc-dev`**（不是只有 `libhwloc15`） |

### 4.1 可选：pip editable（网络 / 编译环境 OK 时）

```bash
apt-get install -y libhwloc-dev pkg-config   # 编译用，与 libhwloc15 不同

cd "$REPO/kt-kernel"
CPUINFER_USE_ASCEND_NPU=1 "$PYBIN" -m pip install -e . --no-deps --no-build-isolation
```

常见失败：

| 报错 | 原因 | 处理 |
|------|------|------|
| `Connection to repo.huaweicloud.com timed out` | pip 源超时 | 跳过 pip，用 §3 symlink 方案 |
| `None of the required 'hwloc' found` | 缺 `libhwloc-dev` | `apt-get install libhwloc-dev pkg-config` |
| `libhwloc.so.15: cannot open shared object file` | 缺运行时库 | `apt-get install libhwloc15` |

### 4.2 重编 C++（`.so` 丢失或改过代码）

见 [Phase0 手册 §2.4](./Phase0_Phase1_变更记录与复现手册.md)：

```bash
mkdir -p /tmp/kt_kernel_build && cd /tmp/kt_kernel_build
cmake "$REPO/kt-kernel" \
  -DKTRANSFORMERS_USE_ASCEND_NPU=ON \
  -DLLAMA_NATIVE=OFF \
  -DLLAMA_ARM_DOTPROD=ON -DLLAMA_ARM_FP16=ON \
  -DLLAMA_ARM_SVE=OFF -DLLAMA_ARM_BF16=OFF -DLLAMA_ARM_I8MM=OFF \
  -DKTRANSFORMERS_CPU_USE_KML=OFF -DKTRANSFORMERS_CPU_MOE_KERNEL=OFF \
  -DPYTHON_EXECUTABLE="$PYBIN" \
  -DCMAKE_BUILD_TYPE=Release
cmake --build . --parallel "$(nproc)"
cp -f /tmp/kt_kernel_build/kt_kernel_ext*.so "$REPO/kt-kernel/python/"
bash "$REPO/tools/p27_e2e_preflight.sh"
```

## 5. 常见报错对照

| 日志 / 报错 | 根因 | 处理 |
|-------------|------|------|
| `ImportError: kt_kernel is not installed` | launch 脚本 `PYTHONPATH=kt-kernel/python`（旧写法） | 确认 launch 已 `source p27_ensure_kt_kernel.sh`；见 §3 |
| `[KT] kt_kernel not available; cannot build GPU expert masks` | 同上 | 同上 |
| `NPU out of memory ... Tried to allocate 4.00 GiB`（加载 MoE 权重时） | KT 未挂上，256 expert 全上 NPU | 同上 |
| `AttributeError: 'ServerArgs' object has no attribute 'get_hf_config'` | 旧 KT 代码 API 不匹配 | 已修：用 `get_model_config().hf_config`；拉最新代码 |
| `libhwloc.so.15: cannot open shared object file` | 缺运行时 hwloc | `apt-get install -y libhwloc15` |
| eager profiling 输出 `( ) 1) 2) 3)...` 退化 | `SGLANG_NPU_PROFILE_ENABLE=1` 强制全程 eager | 验证准确性用 **Graph + PROFILE_ENABLE=0**；profiling 见 [优化路线图](./DeepSeek-V4-Flash_NPU_KT_Profiling_优化路线图.md) msprof 路径 |
| preflight WARN「.so 不在 python/ 下」 | symlink 后路径在 `kt_kernel/` | 已更新 preflight；见 `kt-kernel/kt_kernel/*.so` 即正常 |

## 7. 环境变量备忘

| 变量 | 重启后是否要手设 | 说明 |
|------|------------------|------|
| `ASCEND_RT_VISIBLE_DEVICES` | **是** | 物理 NPU 卡号 |
| `PORT` | 可选 | 默认 8000；与 curl 脚本一致 |
| `SGLANG_NPU_PROFILE_ENABLE` | 验证时用 `0` | `1` 会自动加 `--disable-cuda-graph` |
| `PYTHONPATH` | **否** | launch / preflight 脚本自动设置 |
| `P27_SITE_PATCH=1` | 一般 **否** | 仅旧 `get_hf_config` 补丁；源码已修可不开 |
| `KT_GGUF_TEMPLATE` | 一般 **否** | 默认 `/workspace/models/cache/dsv4_layer{layer_idx}.gguf` |
